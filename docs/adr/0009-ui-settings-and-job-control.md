# ADR-0009 設定は画面から行い、定期処理は短い間隔の起動＋設定上の間隔で制御する

状態: 採用（定期起動の方式は ADR-0013 に置き換え）　日付: 2026-10-12

## 背景

運用者が、X・AI・通知の接続、実行間隔（30〜60分程度）、定型文、安全装置を、画面から変更したい。実行間隔を変えるたびにデプロイやスケジュール変更をするのは手間が大きい。

## 決定

- 実行間隔は設定（DynamoDB）に持つ。EventBridge は15分ごとに `tick` を起動し、有効・非停止・間隔経過のときだけ実行する。ローカルは同じ `tick` を30秒ごとに呼ぶ。
- 秘密情報（Client Secret、AI APIキー、Webhook URL）は画面から書き込み専用で保存する。値は画面にもAPIにも返さない。トークンは画面から書けない。
- X の初回認可は、アプリ自身のコールバック（`/api/x/callback`）で行う。ADR-0008 で想定していたワンショットスクリプトは不要になった。stateとPKCEの検証値は15分で失効し、1回で使い切る。
- 動作モード（モック／実機）は環境変数 `XRONIX_X_MODE` で決め、画面からは切り替えられない。AWSでは実機固定。
- 手動実行と定期実行は、DynamoDBのリースで同時に動かない。

## 結果

- 最短の実行間隔は15分に制限した。
- AWS上のコールバックURLは、API Gatewayの公開URLになる。このルートだけは認証を外す（stateで保護）。デプロイ時に設計する。
- ローカルのAPIは127.0.0.1限定で、書き込みには専用ヘッダーを要求する（他サイトからの操作を防ぐ）。
