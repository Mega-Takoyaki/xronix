# ADR-0017 ログインをAmazon Cognitoにし、Basic認証を廃止する

状態: 採用　日付: 2026-10-18　（ADR-0004を実現し、ADR-0010の認証部分を置き換える）

## 背景

検証環境の認証は、当面のBasic認証だった（ADR-0010）。Basic認証には、試行回数の制限が無く、ログアウトやパスワードの再設定ができない。運用者から、メールアドレスをIDとするログインと、メールによるパスワード再設定が求められた。

## 決定

| 項目 | 内容 |
| --- | --- |
| 認証基盤 | Amazon Cognito ユーザープール。メールアドレスがログインID。自己登録は無効で、ユーザーは1人（スタックが作る） |
| 画面 | 日本語の自前のログイン画面。CognitoのAPI（`InitiateAuth` ほか）を、ブラウザから直接呼ぶ。ホストUIは使わない |
| APIの保護 | API GatewayのJWT検証（IDトークン）。Xのコールバックと、ログイン設定（`/api/auth-config`、公開してよい値だけ）だけが、認証なし |
| Lambdaでの確認 | 検証済みの印（claims）が無ければ401。メールアドレスが `XRONIX_ADMIN_EMAIL` と違えば拒否。設定漏れで公開されない |
| 画面の配信 | 静的ファイルは、認証なしで配信する（ログイン画面を出すため）。中身は公開してよいもの（秘密情報は、APIの先にだけある） |
| パスワード忘れ | メールの確認コード（`ForgotPassword`／`ConfirmForgotPassword`）。メールは Cognito の既定の送信（SESは使わない） |
| 初回 | スタックが、ユーザーを作り、仮パスワードをメールで送る。初回のログインで、新しいパスワードを設定する |
| メールアドレスの扱い | 公開リポジトリに書かない。GitHubのシークレット `ADMIN_EMAIL` から、CloudFormationのパラメータで渡す |
| パスワードの条件 | 12文字以上、英大文字・英小文字・数字 |
| トークン | IDトークン60分、更新トークン30日。ブラウザの localStorage に保存。ログアウトで、更新トークンを失効させる |

## 選択肢

| 案 | 評価 |
| --- | --- |
| Cognito + 自前の画面（採用） | 固定費なし（無料枠 月10,000ユーザーまで）。メール送信とコードの管理をCognitoに任せられる。画面は日本語で作れる |
| Cognito + ホストUI | 実装は少ないが、画面が英語寄りで、見た目と文言を合わせにくい |
| 自前でパスワードとメールを実装 | SESの設定（ドメイン／アドレスの検証、サンドボックス）と、パスワードの保管の責任を負う。リスクが大きい |

## 結果と制約

- Cognitoの既定のメール送信は、1日50通までで、送信元が既定のアドレスになる。迷惑メールに入ることがある。1人用では足りる。
- パスワード認証（`USER_PASSWORD_AUTH`）は、TLS越しにパスワードをCognitoへ送る。SRPより実装が単純。1人用で許容する。
- ユーザープールの `UsernameAttributes` などを変えると、プールが作り直され、ユーザーも消える。
- 仮パスワードの期限（7日）を過ぎた場合や、ログインできなくなった場合の復旧は、CloudShellの `admin-set-user-password`（手順書）。
- 運用者の作業: GitHubのシークレット `ADMIN_EMAIL`、事前準備のスタックの更新（デプロイ用ロールに `cognito-idp:*` を足す）。
- 実機のAWSでの動作（メールの到着、仮パスワードでのログイン、確認コード）は、デプロイ後に確認する。
