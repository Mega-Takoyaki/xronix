# ADR-0015 Bedrockのモデルを、使える一覧から選び、既定は安価なモデルを自動で選ぶ

状態: 採用（利用可否の確認を追加: 2026-10-13）　日付: 2026-10-12　置き換え: ADR-0011 の「既定のモデルID」

## 決定

- 画面で、Bedrockのモデルを選ぶ。選択肢は、設定したリージョンで、いま使えるテキスト出力のモデルと、推論プロファイル（リージョン横断）の一覧（`ListFoundationModels`、`ListInferenceProfiles`）。結果は1時間キャッシュし、「一覧を更新」で取り直せる。
- 提供終了（LEGACY）のモデルと、テキストを出力しないモデルは、出さない。推論プロファイルでしか呼べないモデルは、直接のIDではなく、プロファイルのIDを出す。
- モデルが未選択（空）の間は「自動」。一覧から、安価な小型モデルを、名前で選ぶ。優先順は、GPT-6 Luna → Luna → GPT nano → GPT mini → gpt-oss 20B → Haiku → Nova Micro → Nova Lite → Llama 8B → Mistral 7B → 一覧の先頭。同じ名前のものが複数あれば、リージョンに合う推論プロファイル（`apac.` など）を優先する。
- 選んだモデルは、分類にも、AIで作る返信文にも使う。
- 画面から、一覧に無いIDを直接入力することもできる。

## 理由と限界

- 価格は、APIから取れないため、「安価」は名前で判断している。意図と違うモデルが選ばれた場合は、画面で選び直す。
- 「GPT-6 Luna」というモデルは、作成時点で、実在や正確なIDを確認できていない。一覧に出れば、最優先で選ばれる。出ない場合は、次の候補が選ばれる。
- 一覧に出ることと、利用できる（モデルの利用有効化が済んでいる）ことは別。画面の「接続テスト」で確認する。
- 権限として、`bedrock:ListFoundationModels` と `bedrock:ListInferenceProfiles` を追加した。

## 追加（2026-10-13）: このアカウントで使えるかを確認する

実機で、一覧に出た `openai.gpt-6-luna` が自動選択されたが、「このアカウントでは使えない」（`AccessDeniedException`）で失敗した。`ListFoundationModels` は、リージョンにあるモデルを返すだけで、このアカウントが使えるかは分からないため。

- 一覧を作るとき、各モデルの利用可否を `GetFoundationModelAvailability` で確認する（並行して実行、一覧と一緒に1時間キャッシュ）。次のどれかなら「利用不可」: 利用が許可されていない（`NOT_AUTHORIZED`）、契約・提供の対象外（`entitlement`）、リージョン外、利用規約の同意が未完了。確認できなかったものは「不明」とし、一覧からは除かない。推論プロファイルは、元のモデルの状態に従う。
- 「利用不可」のモデルは、画面で選べない。「自動」の選択も、利用不可のものを除く。
- 「自動」のとき、実行時に拒否（`AccessDenied`、`Validation`、`ResourceNotFound`）されたら、そのモデルを1時間、候補から外し、次の候補を試す（最大3つ）。「一覧を更新」で、外した候補は戻る。
- 画面で選んだモデルは、勝手に差し替えない。拒否されたら、原因と対処（利用可のモデルを選ぶ、推論プロファイルを選ぶ）を日本語で案内する。
- 「接続テスト」は、実際に使ったモデルを表示する。
- 権限として `bedrock:GetFoundationModelAvailability` を追加した。
