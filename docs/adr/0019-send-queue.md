# ADR-0019 送信キュー（自動送信を、間隔をあけて1件ずつ送る）

状態: 採用　日付: 2026-10-18

## 背景

自動送信で、短時間に複数の返信を続けて投稿すると、スパムとみなされたり、表示が制限されたり（シャドウバン）する恐れがある。

## 決定

| 項目 | 内容 |
| --- | --- |
| 対象 | ルールの「承認なしで送信」。設定「承認からの送信も、キューに入れる」をオンにすると、画面（とTelegram）で承認した返信も、キューに入れる（既定はオフ。承認は、人が1件ずつ行うため、即時） |
| キュー | 返信の状態に `send_queued`（送信待ち）を足す。古い順に、1回の起動で、1件だけ送る |
| 間隔 | 設定の「送信の間隔（秒）」（10〜3600、既定120）に、「ランダムな幅（秒）」（0〜1800、既定60）を、前後にランダムに加える（秒まで）。最短5秒 |
| 時刻の登録 | 次の送信の時刻を、EventBridge Schedulerの一回限りのスケジュール（秒単位）で登録する。定期処理と同じ仕組みで、同じ名前の接頭辞（`<スタック名>-next-`）のため、権限の追加は要らない。起動は、ジョブのLambdaで、入力は `{"source": "sendqueue"}` |
| 見守り | 15分ごとの見守りが、予定より2分以上遅れた送信を、代わりに送る。登録に失敗した場合も、同じ |
| 送る時の検査 | 緊急停止、ブロック、文面、1日の送信上限、会話の上限（ADR-0018。キューに入っている他の返信は数えない）。通らなければ、送らず、承認待ち（要確認）に戻す。自動送信の枠は、戻す |
| 取り消し | 画面の「外す」で、承認待ちに戻す（自動送信の枠も戻す） |
| 緊急停止 | キューは、消えずに止まる。解除すると、予定を登録し直す |

## 結果と制約

- 返信の投稿は、これまでどおり再試行しない（結果が不明なら、不明として残す）。
- 送信までに、間隔の分だけ遅れる。最初の1件は、最短15秒後。
- 1件ずつ送るため、自動送信が多いと、キューが長くなる。1日の自動送信の上限（既定5件）が、長さの目安になる。
