# ADR-0016 取得範囲を広げる（自分の@が無い返信と、引用）

状態: 採用　日付: 2026-10-13

## 背景

取得元がメンション一覧（`GET /2/users/:id/mentions`）だけだと、次のものが取れず、ルール（自分の投稿への返信、自分の返信への返信、自分の投稿の引用）が動かない場合がある。

- 返信文に自分の@が無い返信（@を消して返信された場合など）
- 自分の@を含まない引用

また、新着が1回の取得上限（300件）を超えたとき、取得位置を最新まで進めるため、古い分が取れないまま、画面には「次回に持ち越し」と出ていた。

## 決定

| 対象 | 取得方法 | 条件 |
| --- | --- | --- |
| 自分宛ての返信 | 検索 `GET /2/tweets/search/recent`、クエリ `to:自分 -from:自分`。専用の取得位置（`reply_cursor`）で、差分だけを読む | 設定「取得範囲を広げる」がオン、かつ、返信系のルールが有効 |
| 引用 | `GET /2/tweets/:id/quote_tweets`。自分の投稿の引用数（`public_metrics`）が、前回より増えた投稿だけ | 同上で、引用のルールが有効。自投稿の確認の間隔ごと |
| 追いつき | 新着が多いときは、最大10ページ（1000件）まで読む。それでも足りなければ、位置を進め、取れなかったことを正しく表示する | 常に |

- 取り込みは、投稿IDで重複を防ぐ（メンション一覧と検索で同じ投稿が来ても、1回だけ）。
- 検索や引用の取得に失敗しても、メンションの取得は完了とし、ジョブは失敗にしない。ログに警告を残す。
- 初回: 取得を始めたばかりで、初回の動作が「現在地点から」なら、過去分は取り込まない。すでに取得を始めている環境に、この機能が入った場合は、検索で取れる範囲（直近7日）を取り込む。
- 費用: 他人の投稿の読み取りで、約 $0.005／件。実行履歴の概算費用に含める。設定でオフにできる。

## 詳細ログ

取りこぼしの調査のため、ジョブの各段階を、レベル「詳細」（debug）で記録する。設定「詳細ログを残す」（既定オン）でオフにできる。7日で削除。

- 開始時の設定とルールの数、各取得の件数・取得位置・最新ID、取り込み／スキップ（取り込み済み、自分の投稿、ブロック）の理由、使ったルール、終了時の集計
- 取り込んだ反応には、取得元（メンション一覧／返信の検索／引用の取得）を持たせ、画面に出す
- Xのエラー応答は、`title`と`detail`を、警告の文に含める（トークンなどは含まない）
- 投稿の本文は、記録しない

## 結果と制約

- 検索の対象は直近7日。それより古い返信は取れない。
- 自分の投稿のスレッド内で、他人が他人に返した返信は、取らない（ルールの対象外）。
- 実機のXでの動作（検索の可否、課金区分）は、未確認。失敗は、ログの警告で分かる。
