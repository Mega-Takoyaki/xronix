# ADR-0016 取得範囲を広げる（自分の@が無い返信と、引用）

状態: 採用　日付: 2026-10-13

## 背景

取得元がメンション一覧（`GET /2/users/:id/mentions`）だけだと、次のものが取れず、ルール（自分の投稿への返信、自分の返信への返信、自分の投稿の引用）が動かない場合がある。

- 返信文に自分の@が無い返信（@を消して返信された場合など）
- 自分の@を含まない引用

また、新着が1回の取得上限（300件）を超えたとき、取得位置を最新まで進めるため、古い分が取れないまま、画面には「次回に持ち越し」と出ていた。

## 決定

| 対象 | 取得方法 | 条件 |
| --- | --- | --- |
| 自分宛ての返信 | 検索 `GET /2/tweets/search/recent`、クエリ `to:自分 -from:自分`。専用の取得位置（`reply_cursor`）で、差分だけを読む | 設定「取得範囲を広げる」がオン、かつ、返信系のルールが有効 |
| 返信の補完 | 自分の投稿のXの返信数（`public_metrics`）が前回より増えたとき、`conversation_id:投稿ID` の検索（100件まで）で、その会話の「自分宛ての返信」（返信先が自分、または本文に自分の@）を取る。他人同士の返信と自分の投稿は取らない | 同じ設定がオンで、返信系のルールが有効。自投稿の確認の間隔ごと |
| 引用 | `GET /2/tweets/:id/quote_tweets`。自分の投稿の引用数（`public_metrics`）が、前回より増えた投稿だけ | 同上で、引用のルールが有効。自投稿の確認の間隔ごと |
| 追いつき | 新着が多いときは、最大10ページ（1000件）まで読む。それでも足りなければ、位置を進め、取れなかったことを正しく表示する | 常に |

- 取り込みは、投稿IDで重複を防ぐ（メンション一覧と検索で同じ投稿が来ても、1回だけ）。
- 検索や引用の取得に失敗しても、メンションの取得は完了とし、ジョブは失敗にしない。ログに警告を残す。
- 初回: 取得を始めたばかりで、初回の動作が「現在地点から」なら、過去分は取り込まない。すでに取得を始めている環境に、この機能が入った場合は、検索で取れる範囲（直近7日）を取り込む。
- 費用: 他人の投稿の読み取りで、約 $0.005／件。実行履歴の概算費用に含める。設定でオフにできる。

## 詳細ログ

取りこぼしの調査のため、ジョブの各段階を、レベル「詳細」（debug）で記録する。設定「詳細ログを残す」（既定オン）でオフにできる。7日で削除。

- 開始時の設定とルールの数、各取得の件数・取得位置・最新ID、取り込み／スキップ（取り込み済み、自分の投稿、ブロック）の理由、使ったルール、終了時の集計
- 取り込んだ反応には、取得元（メンション一覧／返信の検索／引用の取得）を持たせ、画面に出す
- Xのエラー応答は、`title`と`detail`を、警告の文に含める（トークンなどは含まない）
- 投稿の本文は、記録しない

## 2026-10-18の実機での判明と修正

診断で、「自分の投稿への返信（本文に自分の@あり）」が、メンション一覧と、返信の検索（`to:自分 -from:自分`）の両方に出ないことが分かった。同じ返信は、`from:投稿者 to:自分` と `conversation_id:` の検索には出た。

- 返信の検索の式から、除外（`-from:自分`）を外した（自分の投稿は、取り込みの段階で除外する）。原因が、この除外かは、実機で未確認。
- 確実に出る `conversation_id:` の検索で、返信数が増えた投稿の返信を補う（上の「返信の補完」）。
- 返信の補完は、自投稿の確認の間隔（設定）ごと。短くすると早く拾えるが、自分の投稿の読み取り（約$0.001／投稿）が増える。

## 取得の診断

取りこぼしの調査のため、画面（ジョブ）に診断を置く。

- 投稿のURL／IDから、その投稿を読み（約$0.005、返信先も読むと約$0.01）、返信の種類、返信先が自分か、本文に自分の@があるか、取り込み済みか、取得位置との前後関係、7日の期間を、日本語で判定する。読み取りだけで、取り込みは、明示したときだけ（通常の取り込みと同じ処理）。
- 取り込まれていない他人の投稿には、「検索の確認」を行う（直近7日のみ）。`from:投稿者 to:自分` と `conversation_id:会話ID` の2つの狭い検索で、その投稿が出るかを調べる（結果は最大10件、1件約$0.005）。どれにも出なければ、Xが一覧と検索から外している可能性を示す（2026-10-18、実機で、返信数8のうち7件が取れなかったため追加。推測であり、確認の手段としての機能）。
- 「自投稿の返信数を確認」: 自分の投稿ごとの、Xが数える返信数・引用数と、取り込み済みの件数。差が、取りこぼしの目安。
- 自投稿の確認の詳細ログにも、同じ比較を残す。

## 結果と制約

- 検索の対象は直近7日。それより古い返信は取れない。
- 検索の `since_id` は、7日以内の投稿のIDだけを受け付ける。`0` や古いIDを付けると、HTTP 400（Invalid Request）になる。取得位置が使えない値のときは、`since_id` を付けず、直近7日をすべて読む（取り込みは投稿IDで重複を防ぐ）。2026-10-18に、実機で発生して判明した（空の結果のときに `0` を保存していた）。
- 自分の投稿のスレッド内で、他人が他人に返した返信は、取らない（ルールの対象外）。
- 実機のXでの動作（検索の可否、課金区分）は、未確認。失敗は、ログの警告で分かる。
