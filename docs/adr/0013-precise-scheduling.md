# ADR-0013 次回実行を秒単位の一回限りのスケジュールで登録する

状態: 採用　日付: 2026-10-12　一部置き換え: ADR-0009 の「15分ごとの起動」

## 背景

実行間隔を1〜999分の任意の分数にし、さらに「±X分（1〜99分）」を秒の単位までランダムにずらしたい。15分ごとの固定起動では、1分刻みの間隔も、ランダムな秒での実行もできない。

## 決定

- 実行の終わりに、次回の実行時刻を決め、EventBridge Scheduler の一回限りのスケジュール（`at(yyyy-mm-ddThh:mm:ss)`、秒単位）として登録する。実行後は自動で削除される。
- 次回の時刻 = 前回の開始 + 間隔 + ランダムな秒数。ランダムな秒数は、−ずらし幅×60 〜 +ずらし幅×60 の整数（秒）。ずらし幅が0なら、ずらさない。
- 次回が現在から15秒未満になる場合は、15秒後にする（ずらし幅が間隔より大きい場合など）。
- 設定（有効、間隔、ずらし幅）の変更、緊急停止の切り替え、手動実行のたびに、次回を計画し直す。古い予定は削除する。無効・停止中は予定を取り消す。
- 予定ごとに名前を変える（`<スタック名>-next-<時刻>-<乱数>`）。実行中に新しい予定を登録しても、実行後の自動削除に巻き込まれないため。
- 15分ごとの起動は「見守り」として残す。予定が2分以上遅れている（登録の失敗や取りこぼし）ときだけ、代わりに実行する。
- 予定の起動は、自動の再実行を無効にする（二重実行の防止）。重ねて起動しても、予定時刻に達していなければ何もしない。
- 開始時刻の起点が前回の開始なので、実行時間が長くても、間隔は保たれる。

## 結果

- 実行時刻は、EventBridge Schedulerの精度（通常は数秒以内）で動く。
- Lambdaに、スケジュールの作成・削除と、Scheduler用ロールの `PassRole` を許可した。
- ローカルの開発サーバは、5秒ごとに予定時刻を確認して実行する（Schedulerは使わない）。
- 費用は無料枠内（Schedulerは月1,400万回まで無料）。
