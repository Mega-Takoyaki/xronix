# 横断的concept

## 投稿作成の安全設計

- create は絶対にリトライしない。HTTPクライアント層で、読み取りと投稿作成を別経路にする。
- 送信Lambdaは同期呼び出しのみ。非同期呼び出しを使う場合は再試行回数を0にする。
- 状態 `sending` への条件付き更新に成功した呼び出しだけが送信する。
- 応答が得られない場合は `unknown` とし、運用者がXの画面で確認して解決する。

## アカウント保護

| 仕組み | 内容 |
| --- | --- |
| 日次上限 | 1日の送信数の上限。超えたら送信を拒否 |
| ブロック対象一覧 | 返信しないユーザーID。運用者が管理 |
| 緊急停止 | 設定のフラグ1つで、送信と取得を止める。承認画面から切り替え可 |
| リンク禁止 | 返信文にURLがあれば送信を拒否（料金約13倍の回避） |
| 自動送信の上限 | 承認なしの送信は、1日の自動送信の上限（既定5件）に加え、全体の送信上限・緊急停止・ブロック対象の検査を通る。超えたら承認待ちに回す |
| いいねの上限 | 1日のいいね上限（既定20件）。失敗は数えない |
| 送信キュー | 自動送信は、キューに入れて、設定の間隔（秒、ランダムな幅つき）をあけて、1件ずつ送る（ADR-0019） |
| 会話の上限 | 同じ相手との同じ会話での返信（既定3回）と、同じ相手への1日の返信（既定5回）の上限。超えたら、返信案づくりと自動送信を止める（ADR-0018） |
| 対象の限定 | 自分の投稿に付いた返信、または自分へのメンションのみ |

## 読み取りのリトライ

429／5xxは指数バックオフ＋ジッター。回数に上限を置く。リトライするのは読み取りと冪等な操作だけ。

## 秘密情報

- クライアントID／シークレット、トークンはSSM SecureString。ローカルは `.env`（gitignore）。
- ログにトークン・本文全文を出さない。
- 通知には本文全文を載せない。

## 分類

- 区分: スパム、質問、ポジティブ反応、要注意。
- MVPはルールベース（キーワード、正規表現、メンションの形）。要注意は保守的に広く拾い、人が見る。

## 承認画面のUI

- 日本語。機能説明はⓘのツールチップに集約し、長文を画面に置かない。
- 主操作は「承認して送信」「編集」「却下」「ブロック対象に追加」。

## テスト

- Lambdaの業務ロジックはAWSに依存しない純粋関数に分け、Xクライアントとストレージを差し替え可能にする。
- DynamoDBは moto 等でローカルテストする（条件付き書き込みの競合を含む）。
- 実機確認した範囲としていない範囲を、報告で分ける。
