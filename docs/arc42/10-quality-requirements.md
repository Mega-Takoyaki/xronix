# 品質要求

品質目標は [はじめに と 目標](01-introduction-and-goals.md) を参照。ここではシナリオで具体化する。

| 品質 | シナリオ | 期待する結果 |
| --- | --- | --- |
| 信頼性 | 送信中にXが応答せずタイムアウトする | 再送せず `unknown` にする。運用者が確認するまで同じ返信を送らない |
| 信頼性 | 取得中にXが503を返す | 指数バックオフで再試行。上限後は次回の定期実行で続きから取得 |
| 一貫性 | トークン更新が同時に2回起動する | 1つだけが更新し、もう一方は更新後のトークンを使う |
| 安全性 | 日次上限に達した後に承認する | 送信せず、理由を画面に表示 |
| 安全性 | 緊急停止中に定期実行が起動する | 取得・送信ともに何もしない |
| 安全性 | 返信案にURLが含まれる | 送信を拒否 |
| 費用 | 想定外に読み取りが増える | X側の月上限額で止まる。AWSはオンデマンドで極小 |
| 保守性 | 運用者が1人で変更する | IaCとテストで再現・確認できる |
