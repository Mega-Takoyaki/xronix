# 制約

## 技術的制約

| 制約 | 理由・根拠 |
| --- | --- |
| AWS 東京リージョン ap-northeast-1 | 方針。変更するなら ADR を起こす |
| LambdaをVPCに入れない | NAT Gatewayで月約$32かかるため。外部API（X）へは直接出る |
| Xのリフレッシュトークンは使うたびに入れ替わる | 更新を1か所に集め、排他制御する（ADR-0003） |
| スコープに `offline.access` が必須 | 無いとリフレッシュ時に invalid_grant になる（ReelMillyで確認済み） |
| 必要スコープ | tweet.read tweet.write users.read offline.access |
| 専用のXアプリを使う | ReelMillyと共有すると互いのトークンを無効にする（ADR-0008） |
| 投稿作成はリトライ禁止 | 二重投稿の防止（ADR-0006） |
| 返信にリンクを入れない | リンク付き投稿は料金が約13倍（$0.015→$0.20） |

## 組織的・方針上の制約

| 制約 | 内容 |
| --- | --- |
| 成人向け文脈を Claude（Bedrock含む）に送らない | 運用者の方針。ローカルLLMはLambdaで非現実的 |
| Xの自動化ルール | 自分の投稿に付いた返信への少量の返信に限る。成人向けアカウントは目を付けられやすい |
| 課金が発生する操作は事前に確認 | リソース作成、デプロイ、外部サービスへの送信は、費用見込みを示してから行う |
| 秘密情報 | 表示・コミットしない。`.env` と SSM / Secrets のみ |
